# Контекст для агентов (Hermes / Cursor)

Репозиторий **model** — веб-интерфейс (`web/`), API (`api/`), документация (`docs/`), свод законов `SWOD_ZAKONOV.txt`.

- **Секреты:** только `private/` локально у владельца, не в Git.
- **Деплой статики:** `web/dist` → VPS `/var/www/model/web/` (Mac: `scripts/deploy/deploy.sh`; Hermes на VPS: `scripts/deploy/deploy-on-vps.sh`, см. `docs/environment/DEPLOY.md`).
- **Hermes на сервере:** рабочая копия — `/home/hermes/work/model` (клон этого репо, ветка `hermes/work`). Старый путь `/home/hermes/vault/Projects/model` — не использовать.

## Два агента, одна репа

| | **Hermes (TG)** | **Дас (Cursor)** |
|---|-----------------|------------------|
| Когда | Комп выключен, с телефона | Разработка UI, деплой, сложные правки |
| Где код | VPS, ветка **`hermes/work`** (или `hermes/*`) | Mac, обычно **`main`** + локальные правки |
| Синхрон | Пишет в **`docs/sync/HERMES_HANDOFF.md`**, коммитит | `scripts/sync/pull-hermes-from-vps.sh`, читает handoff |

**Hermes после сессии:** дописать блок в `docs/sync/HERMES_HANDOFF.md`, закоммитить; не пушить в `main` без слова владельца.

**Cursor:** по фразе «сверься с Hermes» — скрипт pull + handoff, потом предложить слияние или перенос патча.

## Hermes onboarding check (обязательный старт)

Перед любой задачей, где нужен содержательный контекст проекта (а не только точечная техпроверка), Hermes сначала делает короткий onboarding.

1. Прочитать:
   - `AGENTS.md`
   - `SWOD_ZAKONOV.txt` (минимум законы 13, 14, 15)
   - `docs/STRATEGY_KONSPEKT.md`
   - `docs/sync/HERMES_HANDOFF.md` (последние записи)
2. В ответе явно зафиксировать:
   - главную цель проекта сейчас;
   - текущий продуктовый фокус (календарь + сущности + метрики);
   - операционные ограничения Hermes (ветка, handoff, private, деплой-порядок).
3. Только после этого предлагать план шагов по задаче.

## Мини-протокол Cursor -> Hermes (короткие шаблоны)

Использовать, чтобы не пересылать длинные сообщения между чатами.

### 1) Старт задачи

```text
Задача: <1 предложение>
Контекст: см. AGENTS.md + SWOD(13/14/15) + docs/STRATEGY_KONSPEKT.md + последние блоки docs/sync/HERMES_HANDOFF.md.
Фокус: веди к главным целям (ритм 2–3 дня/нед, календарь+сущности+метрики, сильная визуализация мастер-админ, вектор дохода 5+ млн/мес).
Формат ответа: что понял (5 буллетов) -> план 3 шага -> выполнение.
```

### 2) Отчёт по выполнению

```text
Дай отчёт по шаблону handoff:
- сделано;
- файлы;
- проверки;
- риски;
- что нужно в Cursor.
Если есть отклонение от главных целей — укажи отдельно в 1–2 буллетах.
```

### 3) Запрос проверки / ревью

```text
Нужна проверка: <что проверить>.
Проверь на соответствие целям проекта и текущему фокусу (календарь+сущности+метрики, UX мастер-админ, операционные правила SWOD).
Дай: критичные замечания -> быстрые правки -> итоговый статус.
```

## Focus guard (оба агента)

Если пользователь уходит в сторону и задача не приближает к главным целям, агент обязан коротко напомнить фокус и предложить ближайший шаг, который возвращает к целям:
- продукт: календарь + сущности + метрики;
- качество и наглядность мастер-админ;
- рабочий ритм 2–3 дня/нед;
- движение к целевому доходу 5+ млн/мес.

При аудите кода смотреть `web/src`, `api/`, `docs/environment/`, не ожидать содержимого `private/`.
